# 추출 변환 최적화 검증 — 2026-10-16

## 적용 내용

1. 기본 색상 및 PBR PNG의 압축 레벨을 9에서 3으로 변경했다. 해상도,
   픽셀, 알파와 채널 해석은 유지하며, 기존 변환 캐시는 그대로 재사용한다.
2. PBR DD0 탐색과 DDS 대체 파일 탐색에 하나의 `ArchiveReader`를 사용한다.
   색인은 필요할 때 한 번 읽고 패키지 핸들을 두 단계에서 재사용한다.
   파일 핸들은 예외 발생 시에도 닫고 색인 메모리를 해제한다. 지원하지 않는
   색인이나 복호화는 기존 네이티브 추출기로 넘긴다. 경로 비교는 대소문자를
   구분하지 않으며 출력 및 패키지 루트 밖의 경로는 거부한다.
3. PBR 캐시 유효성 확인을 실행 내에서 재사용하고 변환 완료 후 갱신한다.
   공유 PNG 해시를 파일별로 한 번 계산한다. 역할과 내용에 따른 중복 제거,
   읽을 수 있는 파일명, 출력 파일과 캐시의 독립 복사 방식은 유지한다.

## 측정 범위와 조건

- PC 프리센, 빌드 13447218, 최고 LOD, 원본 텍스처 크기, OBJ 출력.
- 동일한 기존 GLB 입력으로 **GLB → OBJ·텍스처 변환 단계**를 비교했다.
  게임에서 GLB를 만드는 시간, 장갑 추출, 전체 앱 실행 시간은 포함하지 않는다.
- 변경 전 5.0.81 Python 코드 스냅샷과 변경 후 코드를 각각 명시적으로 로드했다.
- 최초 변환은 양쪽 별도 빈 PNG/PBR 캐시에서 시작했다. MFM 경로 목록만
  동일한 목록으로 미리 준비했다. 반복 변환은 각각 자신의 캐시를 재사용했다.
- 각 조건 1회 측정이다. OS 파일 캐시를 비우지 않았으며 평균 성능 보장은 아니다.

## 출력 검증

- OBJ 파일 SHA-256 동일, 파트 504개와 삼각형 361,679개 유지.
- 기본 색상, 알파 및 PBR을 포함한 공통 PNG 308쌍: 크기, 모드, 픽셀 모두 동일.
- 동일 파일 집합 PNG 용량: 63,052,869 → 69,320,885바이트, 약 9.94% 증가.
- 새 경로에서 선체 MG 맵을 추가로 찾았다. 원본은 `..._Hull_mg.dd0`지만
  이전 요청은 `..._hull_mg.dd0`였다. 정확한 대소문자로 네이티브 추출기에
  요청한 결과와 새 경로가 읽은 원본 바이트가 동일했다. 이에 따라 specular,
  roughness, metalness 출력 3개가 추가됐다. 기존 출력의 누락이나 픽셀 변경은 없다.
- 새 경로는 패키지 색인 1회, 패키지 핸들 5개로 두 탐색 단계를 처리했다.
  캐시 재사용 시에는 색인 로드와 패키지 파일 열기 모두 0회다.

측정 자료는 작업 폴더 `outputs/performance-optimization/`의 `results.json`,
`verification.json`, `canonical-source-verification.json`에 보관한다.
`invalid-import-*`는 Python 고정 경로 문제로 기준 모듈이 잘못 로드된 예비
실행이며 위 결과에서 제외했다.
